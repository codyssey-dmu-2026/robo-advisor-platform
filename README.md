# Robo-Advisor Platform (API Gateway, Web Dashboard & MLOps)

[![Platform checks](https://github.com/codyssey-dmu-2026/robo-advisor-platform/actions/workflows/ci.yml/badge.svg)](https://github.com/codyssey-dmu-2026/robo-advisor-platform/actions/workflows/ci.yml)

에이전틱 RAG + 강화학습 기반 통합 자율 로보어드바이저 프로젝트의 **API 서빙, 웹 대시보드 및 인프라(MLOps)** 파트 레포지토리입니다.

프론트엔드(Streamlit)에서 모델을 직접 로드하지 않는 **MSA(Microservice Architecture) 원칙**을 준수하며, 하위 마이크로서비스(`evaluation-xai`, `agentic-research`, `rl-engine`)를 통합하는 단일 진입점 **API Gateway (`8080`)**와 **6개 필수 탭 기반 대시보드 (`8501`)**를 제공합니다.

## 🔌 5대 필수 API 엔드포인트 명세 (Gateway `8080`)

Swagger UI 문서: 서버 실행 후 `http://127.0.0.1:8080/docs` 접속 (요청·응답 스키마 모두 문서화)

- 요청 형식이 잘못되면 하위 서비스에 보내기 전에 `422`로 거절합니다 (팀원 서비스와 같은 규칙).
- 하위 서비스가 꺼져 있으면 `503`, 제한 시간(요청 1건 5초 기준) 안에 응답하지 않으면 `504`, 그 밖의 오류는 하위 서비스의 상태 코드와 사유를 그대로 전달합니다.
- `/optimize`만 예외로, RL 서버 장애 시 `status: mock_fallback`(동일 비중)으로 응답합니다.

| 메서드 | 엔드포인트 | 설명 | 연동 마이크로서비스 |
|---|---|---|---|
| `GET` | `/health` | 전체 게이트웨이 및 하위 3개 서비스 상태/모델 로드 여부 반환 | `8000`, `8001`, `8002` |

## 🛡️ 리스크 태그 Safe-Guard (에이전트 → 강화학습 연동)

과제 요구사항 "리서치 에이전트가 탐지한 위험 이벤트를 리스크 태그로 변환하여 강화학습 환경의 관측 공간 **또는 리스크 모니터링 모듈**에 반영"을 **리스크 모니터링 모듈** 쪽으로 구현했습니다. `agentic-research`가 만든 `risk_tags.jsonl`을 RL 서빙 서버가 읽기 전용으로 받아, 위험 신호가 강한 자산의 비중을 자동으로 줄입니다.

| 단계 | 규칙 |
|---|---|
| 1. 유효한 태그 고르기 | 결정일 장 마감까지 공개됐고(`available_at`) 아직 만료되지 않은(`expires_at`) 태그만 사용. 결정일 뒤에 공개된 태그는 쓰지 않음(미래 정보 누수 방지) |
| 2. 위험 점수 | 자산별로 유효한 태그 중 최대 `심각도 × 신뢰도` (에이전트의 `RiskTagProvider.vector()`와 같은 정의) |
| 3. 비중 축소 | 점수가 `RISK_TAG_THRESHOLD`(기본 0.5) 이상이면 비중 × (1 − `RISK_TAG_MAX_CUT`(기본 0.5) × 점수). 예: 점수 0.8 → 비중의 40% 축소 |
| 4. 재배분 | 줄인 비중은 신호가 없는 자산에 원래 비율대로 나눔. 자산당 상한(40%)과 비중 합 1.0은 그대로 유지 |
| 5. 태그가 없을 때 | 태그 파일을 읽을 수 없으면 Safe-Guard 없이 모델 비중 그대로 응답 (`risk_guard.available: false`) |

- **결과 (현재 모델, 2025년 평가 구간 259거래일):** 56일 발동, 발동일 평균 6.3%p·최대 30.2%p(2025-04-11, 12개 중 9개 자산에 신호)의 비중을 위험 자산에서 덜어 냈습니다. 대시보드의 포트폴리오 현황(조정 전후 비중)·리스크 모니터링(발동 현황) 화면에서 확인할 수 있습니다.
- **끔/켬 백테스트 (같은 모델, 2025년 258거래일):** Safe-Guard로 바꾼 비중으로 체결하고 그 비중이 다음 날 모델 입력(현재 보유 비중)에 들어가는 폐루프 재생입니다. 거래비용·체결 규칙은 rl-engine 평가와 같고, 끈 쪽 재생은 rl-engine 공개 일별 결과와 258일 모두 일치합니다(최대 차이 8.6e-6, compose가 직접 수집한 가격 데이터의 미세한 차이).

  | 지표 | 끔 (모델 비중) | 켬 (Safe-Guard) | 차이 |
  |---|---:|---:|---:|
  | 누적 수익률 | 44.5% | 46.2% | +1.7%p |
  | 최대 낙폭 MDD | 16.8% | 15.4% | −1.3%p |
  | 샤프비율 | 2.15 | 2.24 | +0.09 |
  | 연환산 변동성 | 17.4% | 17.2% | −0.2%p |
  | CVaR 95% | 2.50% | 2.41% | −0.09%p |

  차이의 대부분은 시장 전체가 급락한 2025년 4월(최대 발동일 04-11 전후)에 생겼습니다. 한 해, 한 모델의 결과라 일반화할 수 없습니다. 기준값(0.5·0.5)은 이 결과를 보고 고르지 않았습니다.
- **이 방식을 고른 이유:** 관측 공간에 넣으려면 `rl-engine` 환경을 바꾸고 모델을 전부 다시 학습해야 합니다. 서빙 단계 규칙은 학습된 모델을 그대로 두고도 위험 이벤트에 즉시 반응하며, 어떤 태그 때문에 얼마나 줄였는지를 출처와 함께 설명할 수 있습니다.
- **한계:**
  - 모델은 리스크 태그 없이 학습됐고, `/performance`(강화학습 성과 화면)의 4년 백테스트 성과는 **이 조정이 반영되지 않은** 모델 원래 비중 기준입니다. 끔/켬 비교는 현재 서빙 모델의 평가 구간(2025년)에서만 했습니다.
  - 시장 전체가 흔들려 대부분 자산에 신호가 붙는 날에는 신호가 없는 소수 자산으로 비중이 몰립니다(자산당 상한 40%까지).
  - 현금 자산이 없어 줄인 비중은 다른 자산으로 옮겨질 뿐 시장 노출 자체는 줄지 않습니다.
- MDD 15% 한도 Safe-Guard(`rl-engine` 학습 환경의 조기 종료 규칙)와는 별개 기능이라 화면과 응답에서 이름을 구분했습니다(`risk_override_applied` ↔ `safeguard_triggered`).

## 🎯 보상 함수 설계 근거

보상 함수는 `rl-engine`이 설계·학습했습니다. 과제 명세의 3종(5개 변형)을 같은 조건(관측 288차원, 연속 행동 + softmax + 자산당 상한 40%, PPO 100,000 스텝, seed 42·43·44)에서 비교했습니다.

| 변형 | 수식 | 설계 의도 |
|---|---|---|
| 단순 수익률 | `r_t` | 위험을 고려하지 않는 기준선 |
| 샤프비율 기반 | `r_t / (σ_t + ε)`, σ는 최근 20일 변동성 | 변동성 대비 수익(위험조정) |
| MDD 페널티 결합 | `r_t − λ · DD_t`, λ ∈ {0.5, 1.0, 5.0} | λ가 클수록 낙폭 억제 우선 (0.5 공격적 ~ 5.0 방어적) |

- **`DD_t`를 현재 낙폭으로 쓴 이유:** 기간 최대낙폭을 쓰면 한 번 크게 빠진 뒤에는 무엇을 해도 벌점이 줄지 않아 회복 행동에 신호가 사라집니다. 현재 낙폭은 고점을 회복하면 0으로 돌아오므로 매일 "낙폭을 줄이는 행동"에 신호가 생깁니다.
- **Safe-Guard 조기 종료 페널티:** MDD 15% 초과 시 에피소드를 끝내되, 일부러 빨리 끝내는 편이 유리해지지 않도록 남은 기간 동안 낙폭이 한도에 머문 만큼의 벌점(λ × 0.15 × Σγᵏ, 최대 λ × 15)을 한 번에 차감합니다.
- **하이퍼파라미터:** 학습률 3e-4, n_steps 2048, 배치 64, γ 0.99, 관측 윈도우 20일. 20일은 과제 권장 범위(20~60) 중 차원이 가장 작아 학습이 빠르고 단기 모멘텀에 민감한 값입니다.

**선택 절차와 결과.** 보상 형태 선택은 각 학습 구간의 마지막 6개월(검증 구간)에서만 했고, 테스트 결과를 보고 고르지 않았습니다(테스트 구간에 맞춰 고르면 성과가 부풀려지기 때문).

| 변형 | 검증 구간 평균 샤프 | 테스트 4년 샤프 (seed 평균) |
|---|---:|---:|
| PPO 단순 수익률 | **0.51** (PPO 중 1위) | 0.85 (seed 42·43·44: 0.77·0.82·0.96) |
| PPO MDD λ=0.5 | 0.37 | 0.80 |
| PPO 샤프비율 | 0.33 | **1.19** |
| PPO MDD λ=5.0 | 0.24 | 0.67 |
| PPO MDD λ=1.0 | 0.19 | 0.83 |
| (참고) 동일가중 | 0.79 | 1.15 |

검증 구간 기준으로는 단순 수익률이 가장 나아서 현재 서빙 모델로 두었습니다. 테스트에서는 샤프비율 보상이 가장 좋았지만, 이 결과를 보고 모델을 바꾸면 선택 절차가 테스트 결과에 맞춰진 것이 됩니다. 어느 쪽을 최종 모델로 할지는 팀 결정 사항으로 남겨 두었습니다. 또한 현재 서빙 모델(seed 42)은 같은 보상의 seed 3개 중 샤프가 가장 낮아, 서빙 모델 하나의 성과는 seed 평균보다 보수적으로 나옵니다. λ 변화에 따른 수익률-MDD 관계는 λ=0.5·1.0·5.0 모두 테스트 MDD 31~34%로 차이가 작았습니다(아래 에러 분석 참고).

**학습 곡선 (Episode Reward).** rl-engine이 git에서 제외한 TensorBoard 기록(`logs/`)을 공유받아 `scripts/export_learning_curves.py`로 `data/learning_curves.csv`를 만들었고, 대시보드 강화학습 성과 화면의 학습 곡선 탭에서 볼 수 있습니다. 실행 120개 모두 100,352 스텝까지 학습했습니다. 보상 함수마다 식이 달라 값의 크기는 서로 비교하지 않고, 같은 보상 함수 안에서 수렴 여부를 봅니다.

## 📐 ANOVA 검증 결과 요약

`evaluation-xai`(`a4b96f4`, `compare-rl`)가 PPO·MVO·동일가중을 같은 실행 조건으로 다시 돌려 계산한 값입니다. 대시보드 ANOVA 화면(`GET /backtest`)과 같은 값이고, 가격·환율·무위험수익률 검증이 남아 있어 **잠정** 결과입니다.

| 검증 | 방법 | 표본 | 효과 | F | p-value | η² | Holm p | 사후 검정 |
|---|---|---|---|---:|---:|---:|---:|---|
| 1. 보상 함수 3종 (단순·샤프·MDD λ=1.0) | One-way | 48개월 × 3종, 월 순수익률 seed 평균 | 보상 함수 | 0.197 | 0.822 | 0.0028 | 1.000 | p ≥ 0.05라 대상 아님 |
| 2. PPO vs MVO vs 동일가중 | One-way | 48개월 × 3전략 (PPO는 MDD λ=1.0 seed 평균, MVO·동일가중은 월간 리밸런싱) | 전략 | 0.545 | 0.581 | 0.0077 | 1.000 | p ≥ 0.05라 대상 아님 |
| 3. 시장 국면별 전략 성과 | Two-way | 검증 2 × 국면(상승 23·횡보 18·하락 7개월) | 전략 | 0.834 | 0.437 | 0.0112 | 1.000 | 국면 효과가 유의해 Tukey HSD 36쌍 수행, 유의한 쌍 0개 |
| | | | **시장 국면** | **6.153** | **0.0028** | **0.0823** | **0.0139** | |
| | | | 전략 × 국면 | 0.259 | 0.904 | 0.0069 | 1.000 | |

- **MVO 비교군:** 매월 첫 결정일에 최근 252개 관측 수익률 공분산으로 최소분산 비중을 구합니다(scipy SLSQP, 합 1·공매도 금지·자산당 상한 40%). 48회 모두 수렴했습니다.
- **국면 판정:** 그달 시작 **전** SPY 60개 관측의 누적 수익률이 +5% 초과면 상승, −5% 미만이면 하락, 나머지는 횡보입니다(미래 정보 미사용).
- **가정 진단:** 검증 1은 등분산·정규성 가정 모두 기각되지 않습니다(Levene p 0.606, Shapiro p 0.074). 검증 2·3은 **등분산 가정이 기각**됩니다(Levene p < 0.001, 0.007). 집단마다 변동 폭이 달라 F 검정 결과를 보수적으로 읽습니다.
- **비유의 해석 (검증 1·2):** η²가 0.003·0.008로 '작음' 기준(0.01)에도 못 미칩니다. 월 수익률 변동 가운데 보상 함수나 전략 차이로 설명되는 부분이 1%도 안 됩니다. 모두 같은 12개 자산·같은 시장 구간에서 운용하고 월 수익률 변동의 대부분이 시장 전체 움직임이라, 전략 차이가 묻힌 것으로 봅니다.
- **유의한 효과 (검증 3):** 시장 국면만 유의합니다(Holm 보정 후에도 p = 0.014, η² 0.082 '중간'). 상승장·하락장 여부가 월 수익률을 크게 좌우하지만, 전략×국면 상호작용이 비유의라 **어느 국면에서도 PPO가 MVO·동일가중보다 뚜렷하게 낫거나 나쁘지 않습니다.**
- **보조 근거, 블록 부트스트랩 (3개월 블록, 5,000회):** PPO − MVO는 월평균 +0.62%p, 95% 구간 [−0.15, +1.37]%p로 0을 포함합니다. PPO − 월간 동일가중은 −0.36%p, [−0.54, −0.16]%p로 블록 1·3·6개월 모두 0보다 작아 **동일가중보다 낮다는 점은 뚜렷합니다.**
- 같은 달을 반복 사용하고 월 수익률에 자기상관이 있다는 점은 ANOVA·Tukey가 보정하지 못하는 한계입니다.

| **검증·테스트 순위가 다름** | 검증 1위 단순 수익률이 테스트에서는 샤프비율보다 낮음. 검증 구간이 6개월로 짧고 같은 설정에서도 seed 간 연도별 샤프 표준편차가 0.06~0.45 | 검증 구간 확대, 여러 윈도우 평균으로 선택, seed 수 확대 |

### 2. 평가 조건의 불일치 (수치를 잠정으로 보는 이유)

`evaluation-xai`가 밝힌 차이입니다. 숫자를 맞추려고 기준을 바꾸지 않고 그대로 적습니다.

- 학습 구간이 고정 4년이 아니라 2018년부터 늘어나는 방식(4~7년)입니다.
- 평가 시 MDD 15% Safe-Guard를 끄고 초과 여부만 기록했습니다. 과제 명세처럼 청산하면 2022년 수치가 달라집니다.
- 미국 8개 + 한국 4개 자산을 공통 통화(FX) 변환 없이 각 통화 수익률로 계산했습니다.
- 동일가중은 매일 리밸런싱(평가 명세는 월간), 벤치마크는 S&P 500 지수 대신 SPY ETF, 무위험수익률 0입니다.
- ANOVA·SHAP용 PPO 재실행은 rl-engine 공개 결과와 64개 중 63개가 엄격한 허용오차(1e-8) 안에서 일치하고, 1개(`ppo_test_w3_simple_s44`)는 float32 계산 수준(약 1e-8)으로 달라 '잠정'으로 표시됩니다.

### 3. 서빙·통합 단계의 한계 (platform)

| 한계 | 영향 | 개선 방향 |
|---|---|---|
| 리스크 태그 Safe-Guard는 서빙 단계 규칙 | 위 성과표는 Safe-Guard 없는 모델 원래 비중 기준. 끔/켬 비교(2025년: 누적 +1.7%p, MDD −1.3%p)는 한 해·한 모델 결과 | 다른 연도 모델에도 같은 비교 적용, 리스크 태그를 관측 공간에 넣은 재학습 모델과 비교 |
| SHAP 설명은 MDD 페널티 모델의 결정 4건 | 현재 서빙 모델(단순 수익률)의 결정 설명이 아니고, 그림은 SPY만 있음 | 서빙 모델·다른 자산·더 많은 결정일로 `explain-ppo` 확대 |
| 평가 결과 묶음을 Release로 배포 | git에 없는 산출물이라 Release(`eval-results-v1`, sha256 검사)에 의존 | 받지 못하면 rl-engine 공개 CSV 분석(검증 1만)과 SHAP 데모로 자동 대체 |
| 새로 실행할 때마다 뉴스를 직접 수집 (재배포 금지) | 한국경제 RSS는 최신 약 50건이라 실행 시점마다 근거 문서가 다르고, DART 키가 없으면 한국 종목 근거가 적음 | `.env`에 `DART_API_KEY` 설정, 데모용 수집 시점 기록 |
| bootstrap이 가격을 다시 수집 | 학습 당시 스냅샷과 미세하게 달라 비중이 소수 넷째 자리에서 차이 | 학습 데이터 스냅샷을 Release로 고정 배포 |
| Windows Docker Compose 5.1.x의 GitHub URL 빌드 버그 | `docker compose up --build`가 실패 | `scripts/build_images.py`로 우회 (README 실행 방법 참고) |

## 🖥️ Streamlit 대시보드 (`8501`)

사이드바 내비게이션, 서비스 상태 표시, 라이트/다크 테마(우측 상단 ⋮ 메뉴의 System·Light·Dark), 모든 차트에 '표로 보기' 제공.

0. **개요:** 현재 모델의 4년 KPI(누적 수익률·샤프·MDD·VaR, 동일가중 대비 차이), 현재 모델·동일가중·SPY 누적 수익률, 자산군 비중
1. **포트폴리오 현황 (`POST /optimize`, `GET /performance`):** 실제 PPO 모델의 기준일별 종목 비중, 자산군 도넛, 리스크 태그 Safe-Guard 조정 내역(조정 전후 비중·근거 태그·발동일 바로가기·반영 토글), 기준일 낙폭 기반 MDD Safe-Guard 상태, 4년 연결 누적 수익률, 비중 변화
2. **강화학습 성과 (`GET /performance`):** 과제 성능 기준 점검(SPY·동일가중 대비 샤프 +0.2, 누적 +10%p), 보상 함수 5종·벤치마크 연도별 비교, 12개 지표 전체 표, 학습 곡선(`GET /learning-curves`: 보상 함수별 seed 3개 곡선, 최종·선택용 학습, 연도별)
3. **SHAP 해석 (`GET /explain/catalog`, `POST /explain`, `GET /explain/plots/...`):** 실제 PPO 결정 4건 × 12개 자산, 기준 비중 → 영향이 큰 8개 그룹 + 나머지 → 결정 비중 폭포 차트, 49개 그룹 전체 표, Summary Plot·Force Plot
4. **에이전트 리서치 (`POST /research`):** 예시 질문, 투자의견 배지·신뢰도, 단계별 추론 과정(Reasoning Trace), 인용 번호가 달린 주장, 원문 링크, 리스크 태그
5. **ANOVA 검증 결과 (`GET /backtest`):** 과제 3대 검증(F·p·η²·Holm p·효과 크기 등급, 유의한 효과 표시), 검증별 해석, 가정 진단, Tukey HSD 사후 검정, 블록 부트스트랩(PPO − MVO, PPO − 동일가중) 신뢰구간
6. **리스크 모니터링 (`GET /performance`, `GET /risk-tags`):** 4년 전체·연도별 VaR·CVaR·MDD 게이지, 낙폭(Underwater) 차트와 -15% 한도선, Safe-Guard 한도 초과 구간 기록 및 상태 알림, 리스크 태그 Safe-Guard 발동 현황(발동일별 축소 비중, 자산별 발동일 수, 근거 태그와 출처), Safe-Guard 끔/켬 백테스트 비교(`GET /risk-tags/backtest`)

ANOVA·SHAP 페이지는 evaluation-xai의 실제 결과(`실데이터 · 잠정` 배지)를 보여 줍니다. 결과 묶음을 받지 못한 환경에서는 rl-engine 공개 CSV 분석과 SHAP 합성 데모(`DEMO` 배지)로 대체됩니다.

## 🚀 실행 방법

### A. 로컬 환경 실행

    # 1. 가상환경 생성 및 패키지 설치
    python -m venv .venv
    .venv\Scripts\activate
    pip install -r requirements.txt

    # 2. RL 서빙 서버 (8002) 및 API Gateway (8080) 실행
    python -m uvicorn rl_server:app --host 127.0.0.1 --port 8002
    python -m uvicorn gateway:app --host 127.0.0.1 --port 8080

    # 3. Streamlit 대시보드 (8501) 실행
    python -m streamlit run dashboard/app.py

### B. Docker Compose 일괄 실행 (권장)

이 레포만 clone하면 됩니다. 팀원 서비스는 GitHub 레포를 **커밋 고정**으로 빌드합니다.

    cp .env.example .env        # 선택: DART 키·SEC 연락처·OpenAI 키 (비워 두면 키 없이 동작)
    docker compose up --build   # Linux / macOS

Windows의 Docker Compose 5.1.x는 GitHub URL 빌드에 버그가 있어 헬퍼로 먼저 빌드합니다.

    python scripts/build_images.py
    docker compose up

첫 실행 시 bootstrap 컨테이너가 팀원 코드로 데이터를 직접 만들고(수 분 소요), 두 번째부터는 건너뜁니다.

| 순서 | 컨테이너 | 하는 일 |
|---|---|---|
| 1 | `data-bootstrap` | data-pipeline: 가격 수집(yfinance/pykrx) → 전처리 → 뉴스·공시 수집(SEC, 한국경제 RSS, DART는 키 있을 때) |
| 2 | `agent-bootstrap` | agentic-research: 뉴스 → ChromaDB 적재, RiskTag 생성 (RL 서빙 서버가 `agent-artifacts` 볼륨을 읽기 전용으로 연결해 사용) |
| 3 | `eval-bootstrap` | evaluation-xai 결과 묶음(`compare-rl`: ANOVA 3종·MVO·실제 SHAP)을 Release [`eval-results-v1`](https://github.com/codyssey-dmu-2026/robo-advisor-platform/releases/tag/eval-results-v1)에서 받아 sha256 확인 후 `results`에 둠. 실패하면 rl-engine 공개 CSV 분석(`import-rl`)과 SHAP 데모로 대체. 평가 코드 커밋·묶음 지문이 바뀌면 자동 재생성 |

평가 API(`evaluation-xai`)는 산출물 폴더를 하나만 읽으므로 같은 이미지를 두 번 띄웁니다. `evaluation-xai`(8000)는 성과·ANOVA(`results`), 내부 전용 `evaluation-xai-explain`은 SHAP 설명(`explain`)을 제공합니다. 결과 묶음을 쓰면 `explain`은 `results`와 같은 폴더를 가리킵니다.

- 뉴스 데이터는 재배포 금지라 git에 올리지 않고 실행 환경마다 직접 수집합니다.
- 다시 수집하려면 `.env`에 `BOOTSTRAP_FORCE=1`, 완전 초기화는 `docker compose down -v`.

### RL 서빙 모델

- `rl-engine`에서 학습한 PPO 모델 번들을 Release [`models-v1`](https://github.com/codyssey-dmu-2026/robo-advisor-platform/releases/tag/models-v1)에 두고, `Dockerfile.rl`이 SHA-256 지문을 확인한 뒤 이미지에 넣습니다.
- 사용할 모델은 `.env`의 `RL_MODEL_NAME`으로 정합니다(기본 `ppo_test_w4_simple_s42`: 2025년 시험 구간, 검증 성적 기준 보상 방식). 값을 바꾸고 `docker compose up -d`만 다시 하면 교체됩니다.
- 서버는 시작할 때 시험 구간 전체를 모델로 재생해 날짜별 비중을 계산하므로 rl-engine 백테스트와 같은 비중이 나옵니다. `as_of`는 그 시각 **전에 끝난 거래일**의 결정만 사용합니다(미래 정보 누수 방지).
- 모델이 학습한 12개 자산 전체만 지원하며, 범위 밖 기준일·일부 자산 요청은 422로 거절합니다. 모델을 쓸 수 없으면 RL 서버는 503을, Gateway는 `status: mock_fallback`(동일 비중)을 반환합니다.
- 로컬 실행 시 `.env.example`의 `RL_REPO_PATH`·`RL_MODELS_DIR`·`RL_DATA_DIR`·`RISK_TAGS_PATH`를 지정하고 `requirements-rl.txt`를 설치합니다.

### C. 개발 모드 (형제 폴더의 작업 중 코드로 빌드)

상위 폴더에 `data-pipeline`, `evaluation-xai`, `agentic-research`, `rl-engine`, `robo-advisor-platform`이 나란히 있을 때:
